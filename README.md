# AutoTuner: 테토 자동 조교

원래 보컬(사람이 부른 노래)과 가사를 넣으면, 보컬의 음 높이 · 꺾기 · 비브라토 · 셈여림 · 숨 섞인 소리 · 힘 준 소리 · 숨 쉬는 자리를
읽어서 **OpenUtau의 카사네 테토가 그대로 따라 부르는 프로젝트(.ustx)** 를 만들어 주는 Mac 앱이에요. 모든 처리는 내 컴퓨터에서 돌아가요.

## 설치와 실행
1. OpenUtau(Mac)와 테토 음원을 설치해 둬요. 음원이 OpenUtau 가수 폴더(`~/Library/OpenUtau/Singers`)에 있으면 저절로 찾아요
   (테토 음원이 여럿이면 기본 목소리를 먼저 골라요. 다른 음원은 앱 오른쪽 위 ⋯ 메뉴에서).
2. 앱 받기 (둘 중 하나)
   - **빌드된 앱**: 저장소의 Actions → 최근 빌드 → `AutoTuner-mac` 을 받아 풀고 `AutoTuner.app` 을 응용 프로그램 폴더로 옮겨요.
     Apple Silicon · 인텔 Mac 모두 돼요 (macOS 14 Sonoma 이상).
     인터넷에서 받은 서명 없는 앱이라 처음 한 번은 막혀요. 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기"를 누르거나,
     터미널에서 `xattr -dr com.apple.quarantine /Applications/AutoTuner.app` 를 실행해요.
   - **직접 빌드**: 이 폴더의 `start-mac.command` 를 더블클릭하면 `.venv` 를 만들고 `/Applications/AutoTuner.app` 도 만들어요
     (Xcode 또는 Command Line Tools 필요). 앱만 다시 만들려면 `mac/build.sh --install`.
3. AutoTuner를 열면 조교 엔진(`server.py`)이 같이 켜지고, 앱을 끄면 같이 꺼져요.
   - 빌드된 앱은 엔진을 앱 안에 갖고 있고, 처음 켤 때 한 번 필요한 Python 패키지를 `~/Library/Application Support/TetoTune` 에 설치해요
     (인터넷 필요, 몇 분). Python 3.9 이상이 없으면 앱이 Apple 개발자 도구 설치를 안내해요.
   - 직접 빌드한 앱은 이 폴더의 `server.py` 와 `.venv` 를 쓰니, 폴더를 옮기면 `mac/build.sh --install` 을 다시 실행해요.

## 쓰는 법
- **보컬 고르기**: 보컬만 있는 파일(wav · flac · mp3 · m4a)을 창에 끌어다 놓거나 왼쪽 위 칸을 눌러 골라요.
  StemMixer에서 분리한 곡은 왼쪽 목록에 저절로 나와요. 고르면 StemMixer의 음표 · 가사(있으면)와 반주(보컬 뺀 나머지 트랙을 합친 것)도 같이 가져와요.
- **가사**: 한 줄에 한 소절씩 적어요(숨 쉬는 곳에서 줄 바꿈). 히라가나 · 가타카나 · 한글 · 로마자, 장음 「ー」 · 「〜」나 「+」(앞 글자 늘이기)를 읽어요.
  일본어 한자는 부르는 읽기로 바꾸고(私 → わたし, fugashi가 있을 때), 조사 は · へ는 わ · え로 불러요. 문장 부호 · 기호는 빼요. 한글 가사는 OpenUtau의 KO→JA 변환으로 일본어 음원이 불러요. 비워 두면 음 높이만 따라가고 가사는 「ら」.
- **음표 파일**(선택): ustx · ust · mid · StemMixer 음표 파일(json)을 주면 음표는 그걸 쓰고, 음 높이 · 크기 · 숨만 보컬에서 읽어요.
- **조교 설정**: 음 높이 따라가기, 비브라토, 음정 보정, 셈여림, 숨 섞인 소리, 힘 준 소리, 숨소리 크기, 숨소리 방식, 음역(자동이면 남자 목소리는 한 옥타브 올림), 빠르기.
- **자동 조교 시작**(⌘⏎) → 끝나면 오른쪽에 미리보기(원래 음 높이 파랑 · 테토 음 높이 빨강 · 음표 · 숨)가 나오고, "OpenUtau에서 열기"로 바로 열어요.
  OpenUtau는 켜질 때만 프로젝트를 받아서, 이미 켜져 있으면 Finder에서 파일을 보여 줘요 (OpenUtau의 파일 → 열기로 열어요).
- **테토로 불러 보고 다듬기**(기본으로 켜짐): 조교가 끝나면 내 Mac의 OpenUtau로 테토가 실제로 부르게 하고, 원래 보컬과 비교해서
  크기 · 음 높이가 어긋난 곳을 세 번까지 고쳐요. 소리가 뚝 끊기던 곳이 많이 줄어요. OpenUtau가 응용 프로그램 폴더에 있어야 하고,
  없으면 이 단계만 건너뛰어요. 앱은 OpenUtau를 `~/Library/Application Support/TetoTune/render-host`에 복사해서 쓰고, OpenUtau 자체는 건드리지 않아요.
- **결과 확인 · 고치기** (오른쪽 미리 보기에서)
  - ▶로 듣고, **원래 보컬 / 테토**를 같은 자리에서 바꿔 들어요. 반주가 있으면 같이 들을 수 있어요. 빈 곳을 누르면 거기부터 들어요.
  - **확인할 곳**: 틀렸을 만한 곳이 위에 표시돼요 (빨강: 틀렸을 가능성이 큼, 주황: 들어 보기). 목록에서 누르면 그 구간으로 가고 ▶로 그 구간만 들어요.
    음 높이를 잘 못 읽은 곳, 음표 높이가 두 음 사이인 곳, 가사가 그 음표에서 시작하는지 확실하지 않은 곳, 테토가 원래와 다르게 부른 곳이에요.
  - **음표를 누르면**: 가사 바꾸기, 음절을 앞 · 뒤 음표로 옮기기, 늘여 부르기(멜리스마, 이 음표는 앞 음절을 이어 부르고 뒤 음절을 한 칸씩 밀기),
    새 음절로(반대로 당기기), 나누기, 다음과 합치기. 합쳐도 테토가 부르는 음 높이는 그대로예요.
  - **끌어서 구간을 고르면**: 그 구간만 설정을 바꿔 다시 조교해요 (소절 경계까지 넓혀서). 음표 · 가사는 그대로 두거나, 음표 나누기부터 다시 할 수 있어요.
    바꾸기 전 음 높이는 점선으로 같이 보여요.
  - **되돌리기**: 고친 것을 하나씩 되돌려요 (30번까지). 고친 뒤에는 "고친 결과로 테토 다시 듣기"로 테토 소리를 새로 만들 수 있어요.
  - 고친 것은 `project.ustx`에 바로 저장돼요. OpenUtau에 이미 열려 있으면 파일을 다시 열어 주세요.
- 가사는 보컬마다 따로 기억해요. StemMixer 곡에 가사가 있으면 가사 칸을 비워 둘 때 그 가사를 써요.
- 결과는 `~/Music/AutoTuner/<곡 이름 날짜>/` 에 저장돼요.
  - `project.ustx`: 테토 트랙, 원래 보컬 트랙(**음소거**, 비교용), 반주(있으면), 숨소리 트랙(음원에 숨소리가 없을 때)
  - `guide_vocals.wav`, `teto_preview.wav`(테토로 불러 본 것, 다듬기를 했을 때), `preview.json`, `report.json`, `refine.json`, `curves.npz`, `.history/`(되돌리기)
  - 예전 이름(TetoTune)일 때의 `~/Music/TetoTune` 결과는 처음 켤 때 `~/Music/AutoTuner`로 옮겨요.
  - 앱에서 결과를 지우면 휴지통으로 옮겨서 되살릴 수 있어요.
- 터미널에서: `.venv/bin/python -m tetotune 보컬.wav 결과폴더 --lyrics 가사.txt [--notes 음표.mid] [--backing 반주.wav]`

## 조교가 어떻게 되는지 (분석)
OpenUtau에서 사람이 "조교"할 때 만지는 것과, 이 앱이 각각을 어떻게 채우는지예요.

| 사람이 하는 조교 | OpenUtau에서 | 이 앱 |
|---|---|---|
| 음표 · 가사 찍기 | 음표(tone, 길이), 가사, 음소 변환기 | 노래 → 음표 모델 GAME(OpenVPI)으로 음표를 나누고 (모델이 없으면 음 높이를 Viterbi로), 크기가 꺼지는 곳 · 소리 빛깔(켑스트럼)이 바뀌는 곳에서 음절을 나눠 가사를 넣어요. 그다음 노래 가사 맞추기 모델 HubertFA로 프레이즈마다 음절의 모음이 시작하는 곳을 소리에서 찾아 음표 경계를 옮기거나 나눠요 (한글은 일본어 음소로 바꿔서). 음표 시작 = 모음 시작이고, 자음은 OpenUtau가 선행발성만큼 앞에 불러요 |
| 음 높이 선(꺾기 · 오르내림) | 음표의 피치 점 + PITD 곡선 (센트) | 음 높이는 AI 둘(RMVPE · SwiftF0)과 WORLD Harvest가 같이 읽고 둘 이상 맞는 값만 써요. 피치 점은 평평하게 두고, OpenUtau가 렌더할 때 음표 사이를 잇는 방식(RenderPhrase)을 그대로 따라 계산해서, 그걸 더해도 원래 음 높이가 되도록 PITD를 5틱마다 넣어요 |
| 비브라토 | 음표 비브라토 | 음표 비브라토는 끄고, 원래 보컬의 실제 떨림을 PITD에 넣어요 (세기 조절) |
| 음정 보정 | 수동으로 선 고치기 | 길게 끄는 음 가운데에서만 3Hz 아래 느린 어긋남을 음표 음 쪽으로 당겨요. 시작 · 끝(꺾기)은 그대로 |
| 셈여림 | DYN 곡선 | 원래 보컬 크기 윤곽(20ms 창, 자음에서 꺼지지 않게 다듬음)을 0.1dB 단위로. 셈여림 0.7(기본)에서 원래 크기 차이 그대로 |
| 숨 섞인 · 힘 준 소리 | BREC · TENC (Worldline-R) | WORLD D4C 비주기성, 스펙트럼 기울기를 곡 안에서 표준화해서 |
| 숨소리 | 숨 음표(息 · 吸 · br) | 노래 안 하는 곳에서 잡음처럼 퍼진 소리를 찾아 그 자리에 숨 음표를 넣고, OpenUtau 자동 음량까지 계산해서 원래 숨 크기에 맞춰요. 음원에 숨소리가 없으면 원래 보컬에서 숨만 잘라 트랙으로 넣어요 |

렌더러는 WORLDLINE-R로 정해 둬요(PITD · DYN · BREC · TENC를 모두 읽어요). 다른 렌더러를 골라도 PITD · DYN은 그대로 써요.

반주 파일이 같이 있으면 (StemMixer에서 불러올 때처럼) 보컬 + 반주(= 원래 곡)에서 보컬 분리 모델 Mel-Band RoFormer로 보컬을 한 번 더 뽑아서,
음 높이 · 음표 · 가사 자리는 그 깨끗한 소리로 읽어요. 크기 · 숨 · 미리 듣기는 원래 보컬 그대로예요.

### 참고한 것
- OpenUtau의 "오디오에서 음 높이 가져오기"(RMVPE): 중앙값 필터 · 튀는 값 다듬기 · 빈 곳 메우기 · 끝 자르기.
- 음 높이 읽기: RVC의 RMVPE(`rmvpe.onnx`, 판 고정) · SwiftF0 · WORLD Harvest를 프레임마다 투표로 합쳐요 (둘 이상이 80센트 안이면 그 값).
  RMVPE 모델은 처음 조교할 때 한 번 받아 `~/Library/Application Support/TetoTune/models/rmvpe`에 둬요. 받지 못하면 Harvest만 써요.
- OpenUtau RenderPhrase: 음표 사이 이음(portamento) · 쉼 앞뒤 처리를 그대로 옮겨서 (tests/test_oupitch.py), PITD를 넣었을 때 OpenUtau가 실제로 부르는 음 높이를 미리 계산해요.
- 가사 맞추기: wolfgitpr/HubertFA v0.0.7 일본어 노래 모델 (처음 조교할 때 받아요, 판 고정 + SHA-256). 디코더는 HubertFA의 것을 옮겼어요.
- 보컬 다시 분리: Kimberley Jensen의 Mel-Band RoFormer 보컬 모델을 audiojs가 ONNX로 바꾼 판 (처음 조교할 때 받아요, 판 고정 + SHA-256).
  STFT는 모델 밖에서 torch.stft와 같게 하고, 긴 곡은 MSST처럼 겹친 조각으로 돌려요. 잔향 제거 모델도 재 봤지만 오히려 나빠져서 쓰지 않아요.
- GAME: OpenUtau의 GAME(음표 가져오기)과 같은 모델 · 같은 순서(encoder → segmenter 8번 → bd2dur → estimator)로 돌려요.
  OpenUtau에 GAME을 설치해 두었으면 그것을, 없으면 처음 조교할 때 OpenUtau 패키지 목록에 있는 판(고정, SHA-256 확인)을 한 번 받아
  `~/Library/Application Support/TetoTune/models/game`에 둬요. 받지 못하면 예전 방법(Viterbi)으로 나눠요.
- OpenUtau의 피치 굽기(BakePitch, UtaFormatix에서 온 RDP 단순화), 숨 음표 넣기(AddBreathNote), 무작위 조교(RandomizeTuning).
- 노래 채보 모델 SOME / GAME(OpenVPI)의 음표 나누기 방식, DiffSinger variance(숨 · 긴장도 곡선을 따로 예측하는 구조).
- UTAU 플러그인 おま☆かせ(테토용 자동 조교)의 "음표 시작 · 끝 처리" 아이디어.

## 시험 결과
소리는 전혀 재생하지 않고, 렌더한 wav를 숫자로만 비교했어요. GitHub의 Mac(Apple Silicon)에서 **공식 테토 음원(TETO-OUset240323)과
최신 OpenUtau Mac 버전**으로 렌더해요 (음원은 시험에만 받고 어디에도 올리지 않아요).

### 가사 맞추기 더 다듬기: PR10 기본 → 새 기본 (`devtools/accuracy.py`의 "새 기본" · "PR10 기본")
PR10 뒤에도 "아직 부정확하다"는 말을 듣고, CSD 12곡에서 음절 시작이 정답과 50ms 넘게 어긋난 곳을 하나씩 나눠 봤어요
(`devtools/diagnose.py`). 78%는 가사 맞추기 모델이 찾은 모음 시작 자체가 틀린 것(가운데값 17ms 늦음),
18%는 프레이즈를 음표로 나누지 못해 가사 맞추기를 통째로 버린 것이었어요. 그래서 `align_fa.py`의 기본을 셋 바꿨어요.
- 이웃 프레이즈 함께 맞추기 (`JOINT` 30초): 프레이즈 하나씩이 아니라 30초까지 이웃과 한 번에 맞춰서,
  음절을 옆 프레이즈에 잘못 넘기던 것도 고쳐요.
- 시간 보정 (`OFFSET` −5ms): 모델이 사람 노래에서 모음 시작을 늦게 찾는 것을 조금 당겨요.
- 덜 버리기 (`SOFT_SPLIT` · `GAP_EXTEND`): 프레이즈 나누기가 조금 어긋나도 버리지 않고 쉼 쪽으로 넓혀서 맞춰요.

세 판 모두 한 실행(c2b72f0)에서 쟀어요. 음표는 리눅스에서 CSD 12곡, 렌더는 Mac에서 4곡씩 (분리한 보컬은 14곡)이에요.

  맞는 음이 이어지는 거라 튀는 소리는 아니에요. 그래서 렌더 비교에 "음표는 맞는데 벗어남"(그 자리 음표가 원래 보컬과 맞는데
  테토만 150센트 넘게 벗어난 곳 = 맞는 음에서 확 떨어지거나 튀는 곳)을 따로 세요.
- 맞는 음에서 정말 튀는 곳은 두 가지였어요: Harvest가 0.1~0.8초씩 한 옥타브 아래 · 위를 읽은 곳, 소리 없음으로 뺀 긴 빈 곳을
  앞뒤 끝 값(잘못 읽힌 값)으로 이어서 수백 ms 동안 엉뚱한 음으로 간 곳.

고친 것: **옥타브 접기** (음표(GAME)에서도, 앞뒤 1초에 읽은 음 높이에서도 한 옥타브쯤 떨어진 조각만, 둘 다 그렇다고 할 때만 접어요)
· **긴 빈 곳은 음표 음으로** (50ms 넘는 빈 곳은 앞뒤 끝 40ms만 잇고 가운데는 그 음표 음).

- 깨끗한 보컬도 좋아졌어요: Harvest가 깨끗한 보컬에서도 가끔 한 옥타브 아래를 읽는데(사람 표시와 비교해서 확인) 그것도 같이 접혀요.
- 재 보고 뺀 것: 음 높이 읽기에서 작은 소리 · 끝 작은 소리 빼기, 주기성(자기 상관)으로 거르기, DIO와 같을 때만 쓰기
  (분리한 보컬에서 모두 그대로이거나 나빠짐), 음표 범위 밖으로 튀는 음 높이 자르기 (깨끗한 보컬이 크게 나빠짐),
  음표만 보고 옥타브 접기 (GAME이 음표를 틀린 곳에서 맞게 읽은 음을 망침).
- 아직 남은 것: 맞는 음에서 벗어나는 곳이 1분에 1번쯤 (음 바뀌는 경계에서 분리한 보컬의 음 높이가 잔향 때문에 늦게 바뀌는 곳 등).
  앱이 "확인할 곳"으로 표시하고, 그 구간을 골라 "음 높이 따라가기"를 낮춰 다시 조교하면 어긋남이 그만큼 작아져요.

### 찾아서 고친 것 (검토)
- 엔진 서버: 같은 Mac의 다른 프로그램이나 웹 페이지가 조교 엔진을 부르지 못하게, 앱이 켤 때마다 만든 비밀값이 있는 요청만 받아요.
  포트는 빈 곳을 골라 쓰고, 앱이 강제로 꺼지면 엔진도 꺼져요. 결과 지우기는 확인을 받은 뒤 휴지통으로 옮겨요.
  조교 중에 앱을 끄면 덜 만든 결과 폴더는 다음에 켤 때 치워요.
- 보안 · 데이터 안정성 (2026-10-21 검토): StemMixer `meta.json`의 트랙 이름 · 음원 `oto.ini`의 샘플 경로가 곡 · 음원 폴더 밖
  (`../`, 절대 경로, 밖을 가리키는 링크)이면 읽지 않아요. 쌓인 작업은 4개까지(넘으면 잠시 뒤 다시), 끝난 작업 기록은 1시간 뒤 지워요.
  엔진을 앱 밖에서 직접 켜도 비밀값을 만들어요. 오디오는 30분 · 16채널, 음표 파일은 20MB · 음표 5만 개까지.
  GAME 모델은 판을 고정하고 크기 · SHA-256 · 압축 안 파일 종류를 확인해요.
  구간 다시 조교: 곡 첫 음절에서 미리 듣기 소리 합치기가 실패하던 문제, 저장 중 멈추면 소리 · 음표 · 미리 보기가 어긋나던 문제
  (모두 임시 파일로 만든 뒤 바꿔 넣고, 되돌리기가 미리 듣기 소리도 되돌려요). 조교가 결과 파일을 다 쓰기 전에 실패하면 새 폴더를 치워요.
  OpenUtau로 불러 볼 때는 AutoTuner 전용 렌더 캐시를 써서, 소리 없는 렌더 때 캐시를 비워도 OpenUtau 캐시는 그대로예요.
- 테토 소리: WORLDLINE-R로 부른 테토는 숨 · ㅅ · ㅎ에도 음높이가 실려서, 숨이 「あ」 음표가 되거나 자음이 따로 짧은 음표가 되어
  가사가 한 칸씩 밀리던 문제. 크기 프레임이 곡 뒤로 갈수록 음높이보다 밀리던 문제(44.1kHz에서 5ms = 220.5샘플).
- 가사: 한자가 섞이면 줄 바꿈이 사라지던 문제, 조사 は · へ (가타카나 ワタシハ · ドコヘ, こんにちは도), ねぇ · ー · 〜,
  영어 줄임말(don't · I’m), Pages · Word에서 붙여 넣은 줄 바꿈, 가사 줄 수와 프레이즈 수가 다를 때 줄 경계 지키기.
  한글 가사를 못 부르는 음원(DiffSinger 등)을 고르면 알려 줘요.
- 음표 파일 · 음원: MIDI 같은 음 겹침 · 화음 · 드럼 트랙, Shift-JIS · 한국어 음원 설정, CVVC 판별, DiffSinger · ENUNU 가수,
  OpenUtau가 못 읽는 AIFF-C 반주는 wav로.
- 앱 · 빌드: 인텔 Mac, pyworld 휠 버전 고정, 보컬 고르기 전에 쓴 가사 유지, 보컬을 빼면 그 곡의 음표 · 반주도 빼기,
  조교 중 종료 확인, 반주 음질 유지, `start-mac.command`가 덜 끝난 설치를 다시 하기.

## 아직 확인 못 한 것 · 한계
- 실제 사용하는 Mac에 깔아 보지는 못했고, 같은 OpenUtau · 테토 음원으로 CI의 Mac에서 시험했어요.
- AI 모델(GAME · RMVPE · HubertFA · 보컬 다시 분리 RoFormer, 합쳐서 1.5GB쯤)은 처음 조교할 때 받아요. 인터넷이 없으면 받지 못한 모델 없이 예전 방법으로 조교해요.
- 반주가 있으면 보컬을 다시 분리하느라 조교가 더 오래 걸려요 (품질을 먼저 골랐어요).
- 가사는 테토 정답 노래 336음절 중 300개쯤 맞고, 사람이 부른 한국어 동요는 음절 시작이 50ms 안에 71% · 100ms 안에 90%예요. 틀린 곳은 OpenUtau에서 고치거나 음표 파일을 주세요.
- 가사를 한 줄로 몰아 쓰면 음절 맞추기가 약해요. 숨 쉬는 곳마다 줄을 바꿔 주세요.
- 사람 노래의 가사 맞추기는 한국어(CSD 동요)로만 쟀어요. 일본어 사람 노래는 정답이 있는 공개 자료를 못 구해서 아직 재지 못했어요.
